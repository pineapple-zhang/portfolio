三步

从零到能对话，只要三步

引擎、模型、启动脚本 —— 这三样凑齐就能用。下面每一步都给出实际的文件名和参数， 照着放、照着改就行。

第 1 步

装引擎：llama.cpp 的 Windows CUDA 版

官方发的 Windows 压缩包，解压到任意目录就能用，不用装 Python、不用编译。 整个目录里只有一个文件是"重"的 —— ggml-cuda.dll， 569 MB，CUDA 的算子全在里面；其余都是几 MB 的小 dll 和 exe。

只要 CPU 也能跑，换不带 CUDA 的那个包就行，代价是慢一个数量级。

第 2 步

挑模型：认准 GGUF 和量化等级

llama.cpp 只吃 GGUF 格式。文件名里的 Q4_K_M 是量化等级 —— Q4 是 4 比特，比原始 16 比特小约四倍，质量损失在日常对话里基本看不出来， 是显存紧张时性价比最高的一档。

多模态（能看图）的模型要两个文件：模型本体 + 一个 mmproj 投影层。-m 指前者，-mm 指后者，缺一个都读不了图。

我的机器实际在用的有三个，共约 11.1 GB（含各自的 mmproj）。

第 3 步

写启动脚本：一行命令 + 几个参数

没有配置文件、没有服务注册。一个 .bat 里就是 一行 llama-server.exe 加一串参数，双击就跑。

出现 server is listening 就说明起来了（冷启动实测 8~20 秒， 2B 最快 8 秒、9B 最慢 20 秒）， 浏览器打开脚本里那个端口就能用。想换模型就改文件名，想换端口就改 --port。

这一页下面有完整脚本，和每个参数的逐条解释。

启动_Qwen3.5-2B.bat 
@echo off
title Qwen3.5-2B (port 8083)
cd /d "%~dp0"

"%~dp0llama-server.exe" ^
  -m  "models\Qwen3.5-2B-Q4_K_M.gguf" ^
  -mm "models\mmproj-Qwen3.5-2B-BF16.gguf" ^
  --fit on ^
  -c 131072 -fa on ^
  -ctk q8_0 -ctv q8_0 ^
  --reasoning off ^
  --host 127.0.0.1 --port 8083

为了看得清拆成了多行，^ 是 cmd 的续行符

怎么选模型要看电脑的配置

怎么按配置选模型

挑模型是一道减法：显存 − 模型文件 − KV 缓存 − 计算缓冲。 减完剩多少，决定的不是"装不装得下"，而是上下文能开多长、有多少层能留在显卡上。

先记住一条换算

Q4 量化下，模型文件差不多是 参数量（B）× 0.6 GB：2B ≈ 1.2、4B ≈ 2.5、9B ≈ 5.3 —— 对着文件名看一眼就知道该往哪一档挑。

但文件大小说明不了显存占用。真正吃显存的是 KV 缓存和计算缓冲， 它们只跟上下文长度有关，跟模型大小关系不大 —— 最小的那个 2B，文件只有 1.83 GB，跑起来照样要吃掉 3.3 GB。

本机实测（6 GB 卡、空闲按 1.47 GB 起算）： 9B@16 K 要 4.06 GB、4B@128 K 要 4.04 GB、2B@128 K 要 3.37 GB。 三个都落在 3.4~4.1 GB —— 9B 看着跟 4B 差不多占，其实有约 2 GB 被 --fit on 挪到内存里跑了。

换成别的显卡怎么挑
你的显存该挑的参数量上下文说明
4 GB2B 级64 ~ 128 K再往上就得靠 --fit on 往内存挪，速度掉一截
6 GB4B 级128 K本机的档位：质量够用，上下文还能开满
8 ~ 12 GB9B 级32 ~ 64 K到这一档，9B 才第一次能整个待在显卡上
16 GB14B 级32 K14B 的 Q4 文件约 9 GB，得给 KV 缓存留位置
24 GB 以上32B 级32 ~ 64 K32B 的 Q4 文件已经 20 GB 上下

第一行到第三行我都用我的电脑实测过，第四、五行是按同一条换算估的 —— 受到资金影响我没在这些卡上跑过，喜欢的朋友可以自行实测。

启动脚本 全文

下面就是 启动脚本 的全部内容， 参数一个都没少。跟原文件只差三处、都不影响运行：

① 命令原本是一整行，这里拆成多行、用 ^ 续行（cmd 里合法）； ② :: 开头的注释是页面上加的，原文件里没有； ③ 缩进空格有微调。删掉注释、把续行接回去，就是原样。

用什么写：记事本（Windows 自带的 Notepad）就够， 不用装任何东西。存的时候记牢两条：

① 「保存类型」选所有文件，文件名写全 xxx.bat —— 不这样会被存成 xxx.bat.txt； ② 「编码」选 ANSI，不要选 UTF-8。 脚本里有中文（那几行 echo），存成 UTF-8 的 .bat 在 cmd 里会显示成乱码。

本机这几个脚本本身就是 ANSI 编码、无 BOM、CRLF 换行 —— 照着存不会错。 用 VS Code / Notepad++ 改也行，但要在状态栏把编码切回 GB2312 或 ANSI，别让编辑器自作主张存成 UTF-8。

启动_Qwen3.5-4B.bat BAT · GBK 
@echo off
:: 窗口标题 + 切到脚本自己所在的目录（用 %~dp0，双击和拖到图标上都对）
title Qwen3.5-4B (port 8081)
cd /d "%~dp0"

echo ========================================
echo   Qwen3.5-4B
echo   端口 8081  -  http://127.0.0.1:8081
echo ========================================
echo   首次加载需要时间，看到 "server is listening" 即就绪
echo   关掉本窗口或按 Ctrl+C 可停止服务
echo ========================================
echo.

:: ↓↓↓ 就是这一行在干活 ↓↓↓
"%~dp0llama-server.exe" ^
  -m  "models\Qwen3.5-4B-Q4_K_M.gguf" ^         :: 模型本体
  -mm "models\mmproj-Qwen3.5-4B-BF16.gguf" ^    :: 多模态投影层（看图用）
  -a  "Qwen3.5-4B" ^                            :: 在网页里显示的名字
  --fit on ^                                    :: 自动决定每层放显存还是内存
  -c 131072 ^                                   :: 上下文 128K
  -fa on ^                                      :: Flash Attention
  -ctk q8_0 -ctv q8_0 ^                         :: KV 缓存量化到 8 位，显存减半
  -np 1 ^                                       :: 只开一个并发槽（一个人用够了）
  --reasoning off ^                             :: 关掉思考链输出，直接给答案
  --host 127.0.0.1 --port 8081 ^                :: 只允许本机访问
  --image-min-tokens 1024 ^                     :: 图片最少切 1024 个 token
  --ui-config-file "ui-config.json" ^
  --jinja ^                                     :: 用模型自带的对话模板
  --ui-mcp-proxy --mcp-servers-config "mcp-config.json"

echo.
echo --- 服务已退出 ---
pause

高亮标出的就是模型和端口出现的地方 —— 换个模型只要动这几处，其余参数不用碰。 ⚠️ 那行大红的 mcp-config.json 里存着搜索服务的 API Key（明文）， 别把这个文件夹打包发给别人。

mcp-config.json 就长这样，密钥填在 env.BOCHA_API_KEY 那一格： 

{
  "mcpServers": {
    "bocha-search": {
      "command": "D:\08 本地大模型\本地部署（多模态llama.cpp）\mcp-env\Scripts\bocha-search-mcp.exe",
      "args": [],
      "env": {
        "BOCHA_API_KEY": "************"
      }
    }
  }
}

上面那串灰色星号就是你自己的博查 API Key 要填的位置 —— 填进去之后文件里存的仍是明文，所以别外传。

参数

这几个参数在做什么

这套参数不是抄来的默认值，是照着 6 GB 显存一点点试出来的。下面每一条都对应过一个问题。

llama-server 启动参数
参数作用为什么这么设
--fit on 自动分配：由引擎自己算每层放显存还是内存 以前写死 -ngl 99（全部塞显存）会直接 OOM。交给它自己算，不再溢出。
-c 131072 上下文长度（token 数），131072 = 128 K 不是越大越好。写 128 K 但显存装不下，层会被挤到 CPU，反而更慢。9B 只给 16 K 就是这个道理。
-ctk q8_0
-ctv q8_0		 把 KV 缓存量化到 8 位 长上下文时 KV 缓存是显存大头。量化后直接减半，质量几乎无感。
-fa on Flash Attention 同显存下能开更长上下文，也更快。
-np 1 并发槽位数 一个人用，开一个就够；开多了每个槽都要占 KV 缓存。
--host 127.0.0.1 只监听本机 默认写 0.0.0.0 的话，同一个局域网里任何人都能连上，而且没有鉴权。
-mm 多模态投影层文件 少了它模型就读不了图 —— 只会把图片当乱码。
--image-min-tokens 1024 一张图最少切成多少个 token 视觉模型的官方建议值。太小会看不清图里的字，太大白占上下文。

能力

本地跑起来之后能做什么

文字、图片、视频、联网 —— 四件事，全部在这台笔记本上完成，数据不出本机。

文字对话

基础能力。上下文给够了就能整篇文档丢进去问。

看图

识别画面内容，也能读图里的文字。实测把发票、截图丢进去都认得出来。

看视频

llama.cpp 靠 ffmpeg 把视频抽成帧再喂给模型，所以引擎目录下要放 ffmpeg.exe 和 ffprobe.exe。 抽帧密度由 --video-fps 控制，默认每秒 4 帧。

联网搜索

接一个搜索服务的 MCP，模型就能查最新信息。 模型自己的知识有截止日期，不联网问它最近的事它只会编。

用完记得把显存还回去

双击停止脚本，或者在黑色窗口里按 Ctrl+C。 脚本会打印停止前后的显存占用 —— 看一眼就知道有没有释放干净。

停止服务_释放显存.bat BAT 
@echo off
title 停止所有本地模型服务
echo ========================================
echo   停止 llama-server 并释放显存
echo ========================================
echo.
echo [停止前] 显存占用:
nvidia-smi --query-gpu=memory.used,memory.total --format=csv,noheader
echo.
taskkill /F /IM llama-server.exe 2>nul
timeout /t 2 /nobreak >nul
echo.
echo [停止后] 显存占用:
nvidia-smi --query-gpu=memory.used,memory.total --format=csv,noheader
echo.
pause

记录

踩过的坑

这些都是真撞过的 —— 左边是当时的现象，右边是现在怎么处理的。

  • 写死 -ngl 99，一把 OOM

    改用 --fit on，让引擎自己算每层放哪。

  • 上下文写 128 K，跑起来却慢得离谱

    按显存给合理值：9B 只给 16 K。开太大反而把层挤到 CPU。

  • 长上下文一开，显存立刻见底

    加 -ctk q8_0 -ctv q8_0 把 KV 缓存量化，显存减半。

  • 服务默认监听 0.0.0.0，局域网里谁都能连

    改成 127.0.0.1，只有本机能访问。

  • 中文界面的 .bat 打开是一堆乱码

    脚本要存成 GBK + CRLF，而且不能靠 chcp 救 —— 一开始就存对。

  • 拖视频进去模型说读不到

    因为缺 ffmpeg.exe。补齐之后还要用 --video-ffmpeg-dir 告诉它去哪找。
